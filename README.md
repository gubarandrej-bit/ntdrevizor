# Ревизор НТД

Система анализа и проверки **проектной и рабочей документации** инженерных сетей на соответствие действующим НТД и законодательству Российской Федерации.

Инженерные системы: электроснабжение, электроосвещение, пожарная сигнализация, СОУЭ, пожаротушение, СКС, ЛВС, ВОЛС, видеонаблюдение, СКУД, охранная сигнализация, АСУ, АСУТП.

## Что система делает

- Ведёт базу НТД и **перед каждой проверкой** пытается подтвердить актуальность (локальный каталог + зондирование правовых порталов). Статусы карточек с порталов автоматически не выдумываются.
- Разбирает входящие файлы **xls / xlsx / doc / docx / pdf / dwg / dxf**; растровые страницы PDF без текстового слоя распознаются постранично через Tesseract OCR (текст помечается как ненадёжный).
- Выполняет **27 детерминированных и ИИ-проверок**, в том числе:
  - актуальность НТД и ссылки на заменённые документы (СП 3.13130.2009, СП 6.13130.2013/2021, ГОСТ 26411-85, ГОСТ Р 21.101-2020, ГОСТ Р 53246-2008 …);
  - комплектность документации;
  - кабельный журнал ↔ спецификация (наименования, количества/длины, тип-сечение) — с учётом составных позиций ОКЛ;
  - оборудование на схемах ↔ спецификация (обозначения ГОСТ 2.710, цепи, перекрёстные ссылки);
  - топология подключений (устройство ↔ клемма/цепь, назначения клемм на цепи, целостность цепей, RS-485);
  - счёт устройств на планах по обозначениям ↔ спецификация (PS*.BTH*/BTM*/BIAL*…);
  - легенда «Условные обозначения» ↔ спецификация (противоречия типов устройств);
  - длины трасс на планах ↔ журнал (PDF-планы по цветным линиям, DXF/DWG);
  - марка и сечение кабеля по нагрузке и ПУЭ табл. 1.3.6 / 1.3.7; согласование автомата и Iдоп;
  - способ прокладки и параметры (радиус изгиба, высота) по СП 76.13330.2016;
  - огнестойкость линий СПЗ (индекс FR);
  - расстановка извещателей по СП 484 табл. А.1 (по площадям экспликации помещений);
  - зоны контроля ЗКСПС и отказоустойчивость (СП 484 Изм. № 1), резервирование линий;
  - совместимость оборудования (адресные/неадресные извещатели↔прибор, искробезопасные цепи↔барьеры, АКБ↔РИП, интерфейсы RS-485/Ethernet/ДПЛС, нагрузка РИП по таблице токов с номиналом из каталога паспортов);
  - расчёт источников питания и АКБ (только по имеющимся числам), прилагаемые арифметические равенства.
- Для ИИ-проверок схем/подключений/расчётов использует **типовые чек-листы по ГОСТ 2.701/2.702/2.709/2.710 и СП 484** (`data/ai_checklists.json`).
- Подключает **локальные и облачные** бесплатные нейросети в режимах *локальный / облачный / гибридный*.
- Пишет в диалоговое окно **перечень проверок**. Если проверка не проводилась — указывает причину.
- Формирует отчёт с замечаниями **критическими и некритическими** и ссылками на пункты НТД (DOC, XLS) и ведомость объёмов работ (XLS).
- Аутентификация по логину и паролю. Администратор через веб: добавление, удаление, смена пароля, блокировка.

## Чего система не делает

Три правила зашиты в движок и в системный промпт модели:

1. Если исходных данных не хватает — **ничего не придумывается**, запрашивается недостающее.
2. Непроведённая проверка **всегда** сопровождается причиной.
3. Ответ даётся **как есть**, без «типовых» коэффициентов спроса, запасов длины, освещённостей и ёмкостей АКБ.

## Подбор бесплатных нейросетей

| Где | Модель | Зачем | Ограничение на вашем сервере |
|---|---|---|---|
| Локально | **Ollama** `qwen2.5:1.5b` / `llama3.2:1b` | Классификация, короткие извлечения | AMD FX-8120 без AVX2, 24 ГиБ RAM, диск 60 ГиБ |
| Локально | **GGUF** Qwen2.5-1.5B Q4_K_M через llama.cpp | То же, без Ollama | Сборка **без AVX2/FMA/BMI2/F16C** |
| Облако РФ | **GigaChat** (Сбер), бесплатный PERS | Русский инженерный текст | Ключ на developers.sber.ru |
| Облако РФ | **YandexGPT Lite** | Русский текст | грант / ключ Yandex Cloud |
| Облако | **Google Gemini 2.0/2.5 Flash** | Качество + большой контекст, PDF/текст | AI Studio, без карты |
| Облако | **Groq** Llama 3.3 70B | Скорость | console.groq.com |
| Облако | **OpenRouter** `:free` | Запасной пул | лимиты 50–200 запр./сут |

**Не ставить на этот хост:** модели 7B+ (диск и скорость), GPU HD 7950 3 ГБ (GCN 1.0, современные бэкенды LLM её не используют).

Рекомендация: **гибрид** — сверки всегда локально и детерминированно; ИИ — Gemini Flash или GigaChat для схем и текстовых расчётов. Без ключей система **работает**: ИИ-проверки помечаются как не проведённые с причиной.

## Свои облачные модели через API

Любой OpenAI-совместимый endpoint (`/chat/completions`) можно добавить, обновить,
проверить и удалить через API без правки `.env` и без перезапуска сервиса. Модель
сразу появляется в каталоге `GET /api/models` (раздел `cloud`, id вида
`custom:<slug>`) и её можно выбирать при создании проверки. Хранится в
`data/custom_models.json` (права 0600, в git не попадает); API-ключ наружу не
отдаётся — только маска `…последние4`.

```bash
TOK=$(curl -sS -X POST $HOST/api/auth/login -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"…"}' | python3 -c 'import sys,json;print(json.load(sys.stdin)["token"])')

# список своих моделей
curl -sS $HOST/api/models/cloud -H "Authorization: Bearer $TOK"

# добавить (только админ); id вида custom:<slug> вернётся в ответе
MID=$(curl -sS -X POST $HOST/api/models/cloud -H "Authorization: Bearer $TOK" -H 'Content-Type: application/json' \
  -d '{"name":"Провайдер X","base_url":"https://api.example.com/v1","model":"qwen2.5-vl-7b","api_key":"sk-…"}' \
  | python3 -c 'import sys,json;print(json.load(sys.stdin)["id"])')

# проверка соединения (короткий запрос, тайм-аут 25 с)
curl -sS -X POST "$HOST/api/models/cloud/$MID/test" -H "Authorization: Bearer $TOK"

# изменить поля (ключ можно не передавать — останется прежний; "" — стереть)
curl -sS -X PUT "$HOST/api/models/cloud/$MID" -H "Authorization: Bearer $TOK" \
  -H 'Content-Type: application/json' -d '{"name":"Провайдер X (2GPU)"}'

# удалить (только админ)
curl -sS -X DELETE "$HOST/api/models/cloud/$MID" -H "Authorization: Bearer $TOK"
```

Добавление/обновление/удаление — роль `admin`; просмотр и тест — любой вошедший.
Все изменения пишутся в журнал действий. Если модель удалена, а на неё ссылается
старая проверка, ИИ-этап честно сообщит «Модель не найдена — возможно, удалена»,
ничего не подставляя. В веб-интерфейсе то же доступно на странице «Настройки».

```
ntdrevizor/
  app/                 backend FastAPI + веб-интерфейс
  data/                каталог НТД, таблицы ПУЭ, реестр проверок
  samples/             контрольный комплект документации
```

## Быстрый старт для разработки

```bash
python3 -m venv .venv
. .venv/bin/activate
pip install -r requirements.txt
python samples/make_samples.py
python -m app.seed
python -m uvicorn app.main:app --host 0.0.0.0 --port 8080
```

Откройте http://127.0.0.1:8080
